## The problem

Research papers like *Attention Is All You Need* and *BERT* are dense, and a general chatbot will happily answer questions about them from memory, including when it's wrong. I wanted a study assistant that answers only from the papers themselves, shows where each answer came from, and refuses when the papers don't cover the question.

## How it works

<Note text="The index lives inside the image, so the app never starts with a missing or mismatched one.">

The nine papers are split into 562 sentence-aware chunks of up to 512 tokens and embedded locally with sentence-transformers. The vector index is built when the Docker image is built, so every deployed copy ships with an index that matches the corpus.

</Note>

When a question comes in, it passes through three guardrails before anything is generated: a semantic check that it's about the corpus at all, a confidence threshold on what retrieval found, and a filter on the quality of the sources. Only then does GPT-OSS 20B, served through Groq, write an answer. The React front end shows the sources alongside the answer in real time.

## Key decisions

<Note text="A separate held-out set keeps the reported numbers honest: they come from questions the thresholds weren't tuned on.">

**Refuse rather than guess.** The guardrail thresholds were tuned by grid search, and the refusal results are reported on a separate, frozen held-out set of 20 questions.

</Note>

**A different model does the grading.** The evaluation harness runs offline retrieval and guardrail metrics, then scores answers with RAGAS using a separate 120B model as the judge, so the generator isn't marking its own work.

**Tests and deploys on every push.** A GitHub Actions pipeline lints the code, runs 43 unit and integration tests, builds the Docker image and deploys it to Hugging Face Spaces whenever `main` changes.

## What the evaluation caught

<Note text="The held-out faithfulness is still 0.79, lower than the tuning-set figure. Closing that gap is what I'm working on now.">

Two of the most useful results were problems, not scores. The harness showed retrieval was far worse than it should be; the cause was a stale vector index, and rebuilding it raised Hit@3 from 0.33 to 0.96. It also pointed to a prompt weakness, and fixing it lifted faithfulness from 0.79 to 0.90 on 16 paired tuning-set questions.

</Note>
